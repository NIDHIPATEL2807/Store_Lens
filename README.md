# Purplle Store Analytics — Computer Vision Pipeline

> Converts raw CCTV footage from 2 Purplle beauty stores into structured retail analytics: visitor counts, zone dwell times, staff detection, group entry, re-identification, and a live REST API.

---

## Architecture at a glance

```
Raw CCTV mp4
     │
     ▼
┌─────────────────────────────────────────────────────────────┐
│  L1  Store Layout    → store_layout.json  (zone polygons)   │
│  L2  YOLOv8+ByteTrack → tracks.jsonl    (per-frame bboxes)  │
│  L3  Zone Assign     → zone_events.jsonl (ENTER/EXIT/DWELL) │
│  L4  Entry/Exit Gate → entry_events.jsonl (ENTRY/EXIT)      │
│  L5  Staff + Re-ID   → reid_events.jsonl (visitor IDs)      │
│  L6  Event Merge     → events.jsonl     (final clean stream) │
│  L7  FastAPI + SQLite → REST API on :8000                   │
└─────────────────────────────────────────────────────────────┘
```

## Run the full pipeline

```cmd
cd pipeline
run_pipeline.cmd
```

This runs L2 → L3 → L4 → L5 → L6 → L7 (API start + event ingest) for both stores.

### Or step-by-step

**L2 — Detection**
```cmd
cd pipeline\L2_Detect
python run_l2.py --layout "..\L1_StoreLayout_selfannotate\output\Store 1\store_layout.json" ^
                 --video  "..\L1_StoreLayout_selfannotate\input\Store 1\CAM 1 - zone.mp4" ^
                 --clip_start 2026-03-08T10:00:00Z
```

**L3 — Zone Assignment**
```cmd
cd pipeline\L3_ZoneAssign
python run_l3.py --tracks_dir "..\L2_Detect\output\STORE_STORE_1" ^
                 --layout     "..\L1_StoreLayout_selfannotate\output\Store 1\store_layout.json" ^
                 --output_dir "output\store1"
```

**L4 — Entry/Exit**
```cmd
cd pipeline\L4_entry
python run_l4.py --zone_events_dir "..\L3_ZoneAssign\output\store1" ^
                 --layout          "..\L1_StoreLayout_selfannotate\output\Store 1\store_layout.json" ^
                 --output_dir      "output\store1"
```

**L5 — Staff Detection + Re-ID**
```cmd
cd pipeline\L5_reid
python run_l5.py --tracks_dir   "..\L2_Detect\output\STORE_STORE_1" ^
                 --entry_events "..\L4_entry\output\store1\CAM_ENTRY_01__CAM 3 - entry_zone_events_entry_events.jsonl" ^
                 --videos_dir   "..\L1_StoreLayout_selfannotate\input\Store 1" ^
                 --layout       "..\L1_StoreLayout_selfannotate\output\Store 1\store_layout.json" ^
                 --output_dir   "output\store1"
```

**L6 — Event Merge**
```cmd
cd pipeline\L6_emit
python run_l6.py --zone_events  "..\L3_ZoneAssign\output\store1\CAM_ZONE_01__CAM 1 - zone_zone_events.jsonl" ^
                 --entry_events "..\L4_entry\output\store1\CAM_ENTRY_01__CAM 3 - entry_zone_events_entry_events.jsonl" ^
                 --reid_events  "..\L5_reid\output\store1\reid_events.jsonl" ^
                 --layout       "..\L1_StoreLayout_selfannotate\output\Store 1\store_layout.json" ^
                 --store_id     STORE_STORE_1 --output_dir "output\store1"
```

**L7 — API**
```cmd
cd pipeline\L7_api
uvicorn main:app --app-dir app --host 0.0.0.0 --port 8000
```

**Ingest events**
```cmd
cd pipeline\L7_api
python ingest.py
```

## API Endpoints

Base URL: `http://localhost:8000`
Interactive docs: `http://localhost:8000/docs`

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/events/ingest` | Batch ingest (up to 500 events). Idempotent. Returns 200/207/400 |
| `GET` | `/stores/{id}/metrics` | Unique visitors, conversion rate, avg dwell, queue depth, abandonment |
| `GET` | `/stores/{id}/funnel` | Entry → Zone → Billing → Purchase with drop-off % |
| `GET` | `/stores/{id}/heatmap` | Zone visit frequency, 0–100 score, dwell time |
| `GET` | `/stores/{id}/anomalies` | BILLING_QUEUE_SPIKE · CONVERSION_DROP · DEAD_ZONE |
| `GET` | `/health` | DB ping, uptime, per-store last event, stale feed warning |

### Sample responses

```bash
curl http://localhost:8000/stores/STORE_STORE_1/metrics
# → {"store_id":"STORE_STORE_1","date":"2026-03-08","unique_visitors":46,
#     "conversion_rate":0.0,"avg_dwell_by_zone":[...],"current_queue_depth":0,"abandonment_rate":0.0}

curl http://localhost:8000/stores/STORE_STORE_1/anomalies
# → {"anomalies":[{"anomaly_type":"DEAD_ZONE","severity":"INFO","description":"Zone AQUALOGICA..."}]}

curl http://localhost:8000/health
# → {"status":"UP","db_latency_ms":1.2,"uptime_seconds":42.1,...}
```

## Staff Detection

L5 uses a two-stage approach:
1. **Uniform colour detection** — HSV colour histogram matching against store uniform palette
2. **Groq VLM fallback** — `meta-llama/llama-4-scout-17b-16e-instruct` via Groq API for ambiguous crops

Staff crops saved to `pipeline/L5_reid/output/store1/staff_crops/`:

## Tech stack

| Component | Choice |
|---|---|
| Person detection | YOLOv8n (ultralytics) |
| Multi-object tracking | ByteTrack (built into ultralytics) |
| Re-ID embeddings | OSNet x0.25 (torchreid, 512-d) |
| Staff VLM fallback | Groq — llama-4-scout via API |
| Zone geometry | Shapely point-in-polygon |
| API framework | FastAPI + uvicorn |
| Database | SQLite (WAL mode) |
| Validation | Pydantic v2 |
| Tests | pytest + httpx TestClient |
